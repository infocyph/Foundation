# Foundation 2.1.0

Foundation 2.1.0 adds an opt-in OAuth authorization-server and resource-token
capability to the existing authentication system. OAuth is disabled by default;
disabled deployments retain the Foundation 2.0 authentication behavior and do
not load OAuth stores, schema, signing keys or bearer-token services.

## Added

- Authorization Code with mandatory PKCE S256, Client Credentials and rotating
  Refresh Token grant flows.
- Asymmetric OAuth access tokens, JWKS, authorization-server metadata,
  revocation, introspection and durable replay/reuse protection.
- Exact redirect validation, bounded protocol input, scope-to-permission mapping,
  resource-audience policy and OAuth-specific rate-limit adapters.
- Additive OAuth persistence with schema install, upgrade, rollback and
  concurrency coverage.
- OAuth client, authorization, key-readiness and pruning administration through
  the existing Foundation CLI.
- OAuth bearer-principal resolution through the existing principal,
  authorization and middleware system without creating a second auth stack.

## Compatibility and upgrade

- PHP support remains `^8.4`.
- Existing application bearer tokens remain separate from OAuth access tokens;
  neither token profile is accepted by the other profile's resolver.
- The OAuth schema revision is additive and preserves Foundation 2.0 account,
  session, MFA and application-token data.
- Deploy with OAuth disabled first. Provision the database and signing keys,
  validate production configuration, install the auth schema revision, check
  key/application readiness, and only then expose application OAuth routes.

See the [OAuth 2.1 extension guide](../oauth-2.1.md) for configuration, key
rotation, client-secret handling, deployment, canary and rollback procedures.

## Verification boundary

- The permanent PHPForge release guard passed after temporary F7-only tooling
  was removed: Composer validation/constraints/audit, PHPProbe, Pest, Pint,
  PHPCS, Deptrac, PHPStan, Psalm security/taint analysis and Rector are green.
- The complete local suite passed 253 tests with 15,085 assertions. The focused
  OAuth protocol run passed 67 tests with 12,645 assertions and no skips.
- The recorded Foundation 2.0 comparison measured a candidate median of
  1,121,033.65 RPM against a 1,102,806.56 RPM baseline on the identical
  OAuth-disabled application bearer path, within the two-percent regression
  budget.
- Shared-backend contention and dependency/runtime coverage is recorded in the
  PHP 8.4/8.5 integration-service matrix referenced by `foundation-plan.md`.

This release does not claim that an external OAuth conformance suite passed and
does not add OpenID Connect, dynamic client registration, device flow, password
grant, implicit grant, DPoP, PAR or a generic social-login abstraction. Infbyte
owns only the thin application route and presentation integration after this
Foundation release is tagged.
